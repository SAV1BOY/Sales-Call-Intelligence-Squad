# Post-Call Learning Loop — Loop de Aprendizado Pós-Call

> Toda call alimenta quatro repositórios: registries, objections library, win patterns e swipe file. Nada se perde.

## Origem

Framework de gestão de conhecimento inspirado em conceitos de learning organization (Peter Senge, "The Fifth Discipline") e kaizen (melhoria contínua japonesa), adaptado para operações de vendas de high-ticket. A premissa é que cada call é um ativo de inteligência, não apenas uma oportunidade de venda.

## Conceito Central

A maioria das operações de vendas trata cada call como evento isolado. O closer faz a call, fecha ou não, e passa para a próxima. Todo o aprendizado se perde.

O Post-Call Learning Loop transforma cada call em fonte de melhoria contínua, alimentando quatro repositórios:

1. **Registries** — Dados estruturados de cada call (score, resultado, perfil do lead)
2. **Objections Library** — Biblioteca viva de objeções encontradas e tratamentos testados
3. **Win Patterns** — Padrões extraídos de calls ganhas
4. **Swipe File** — Frases, técnicas e abordagens que funcionaram

Nada se perde. Cada call torna a operação mais inteligente.

## Fase da Call Onde se Aplica

**Pós-call (imediatamente após)**. O loop é executado dentro de 30 minutos após cada call, quando a memória está fresca. Atrasar reduz a qualidade da captura.

## Como Funciona

### Repositório 1 — Registries (Registros)
Para cada call, registrar:
- Data, closer, lead (anonimizado se necessário)
- Resultado: fechou / não fechou / follow-up
- Score total e por bloco
- Duração total e por fase
- Objeção principal
- Perfil do lead (ticket, segmento, nível de consciência)
- Notas qualitativas

**Uso:** Alimenta Win-Loss Pattern Mining e análise de tendências.

### Repositório 2 — Objections Library (Biblioteca de Objeções)
Para cada objeção nova ou relevante:
- Tipo (taxonomia: dinheiro, tempo, cônjuge, confiança, timing, pensar)
- Frase exata do lead
- Contexto (quando surgiu, o que antecedeu)
- Tratamento usado pelo closer
- Resultado do tratamento (resolveu / não resolveu)
- Tratamento alternativo recomendado (se aplicável)

**Uso:** Closers consultam antes de calls. IA usa como referência para coaching.

### Repositório 3 — Win Patterns (Padrões de Vitória)
De calls ganhas, extrair:
- O que o closer fez de diferente/especial
- Qual framework foi mais eficaz
- Qual frase/momento foi decisivo
- Perfil do lead que mais converte
- Condições que favoreceram o fechamento

**Uso:** Replicar o que funciona. Treinar outros closers nos padrões vencedores.

### Repositório 4 — Swipe File (Arquivo de Referências)
Frases específicas que funcionaram excepcionalmente:
- Perguntas de discovery que geraram revelações profundas
- Reframes que mudaram crenças
- Analogias que clarificaram valor
- Respostas a objeções que converteram
- Frases de fechamento eficazes

**Uso:** Closers estudam antes de calls. Novos closers aprendem com material real.

## Aplicação Prática na Call

Após cada call, o closer (ou IA) executa:

1. **2 minutos:** Preencher registry básico (resultado, score, objeção)
2. **3 minutos:** Se houve objeção nova, adicionar à library
3. **2 minutos:** Se fechou, anotar o que fez a diferença (win pattern)
4. **3 minutos:** Anotar 1-2 frases que funcionaram ou deveriam ter sido ditas (swipe)

Total: 10 minutos pós-call. Investimento pequeno com retorno composto.

## Sinais de Boa Execução

- Todos os 4 repositórios são alimentados regularmente — nenhum fica vazio
- Objections Library tem 50+ entradas com tratamentos documentados — base rica
- Win Patterns são usados em treinamentos — conhecimento é transferido
- Novos closers consultam o swipe file — aceleração de ramp-up

## Sinais de Falha

- Loop não é executado — calls são tratadas como eventos isolados
- Apenas registries são preenchidos — os outros 3 repositórios ficam vazios
- Dados não são analisados — repositórios existem mas ninguém consulta
- Loop feito 3 dias depois — memória já se degradou, dados são imprecisos

## Critérios de Avaliação no Scorecard

| Critério | Peso | Evidência esperada |
|----------|------|-------------------|
| Registry preenchido em 30 min | 3 | Dados básicos registrados rapidamente |
| Objeção documentada na library | 2 | Objeções novas capturadas |
| Win pattern extraído (se fechou) | 3 | O que fez a diferença documentado |
| Swipe file atualizado | 2 | Frases eficazes registradas |
| Consistência ao longo do tempo | 3 | Loop executado em 90%+ das calls |

## Frameworks Complementares

- **Win-Loss Pattern Mining** — Usa dados dos registries para análise macro
- **Call Scoring Model** — Score alimenta o registry
- **Rewrite the Moment** — Rewrites alimentam o swipe file
- **RalphLoop Sales** — O post-call loop é uma etapa do ciclo de melhoria

```
- "São R$1.000 por mês — menos do que você perde por semana sem resolver isso"
- "Você me disse que tá 'sangrando dinheiro'. Eu tô te mostrando o torniquete."
```

## Erros Comuns

1. **Não fazer o loop** — O erro mais comum. Closer termina a call e vai para a próxima sem documentar nada.
2. **Fazer apenas o registry** — Preencher dados básicos sem capturar aprendizados qualitativos (objeções, padrões, frases).
3. **Fazer tarde demais** — Loop feito no final do dia ou no dia seguinte. A memória degrada rapidamente — detalhes importantes se perdem.
4. **Não consultar os repositórios** — Alimentar sem usar. Os repositórios precisam ser consultados ativamente antes de calls e em treinamentos.
5. **Repositórios desorganizados** — Informação jogada sem estrutura. Os repositórios precisam de formato padronizado para serem úteis.
